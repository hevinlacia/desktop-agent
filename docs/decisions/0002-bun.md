# 0002：包管理器从 pnpm 换到 Bun

- 状态：已采纳（2026-11-26）
- 关联：[0001](0001-electron.md)（Electron 迁移时沿用了项目原有的 pnpm，本条把它换掉）

## 背景

迁到 Electron 时沿用了项目原来的 pnpm 11.7.0，没有重新选型。当天就暴露了两个问题，都是 pnpm 自身造成的：

1. **配置静默失效**。pnpm 11 把全局配置从 `~/.config/pnpm/rc` 换成了 `~/.config/pnpm/config.yaml`，不再读旧文件。原有的 `verify-deps-before-run=false` 就这样失效，`pnpm build` 开始先自动 install。
2. **冷却期闸门与依赖的发布节奏冲突**。pnpm 11 默认拒绝安装发布不满 24 小时的包。pi 更新很勤（1.6.0 → 1.6.1 只隔 5 天），每次跟进新版都可能被拦住大半天。

另外，仓库规范（`typescript-fullstack.md`）本来就写着「优先 Bun」。

## 决定

用 Bun 做包管理和脚本入口。构建工具（tsc、vitest、electron-vite、electron-builder）和 Electron 本身仍然跑在 Node 上——Electron 自带 Node 运行时，Bun 代替不了，也不需要它代替。

## 换的时候查清的事实

| 事实 | 依据 |
|---|---|
| Bun 不把 `.npmrc` 的自定义键传给脚本 | 临时工程实测，postinstall 里 `npm_config_electron_mirror` 为 `null` |
| 脚本里的 `node` 仍是系统 Node，不会被 Bun 顶替 | 同上，`process.execPath` 是 `/usr/bin/node` |
| Electron 45 的包里没有任何安装脚本 | `node_modules/electron/package.json` 的 `scripts` 为空 |
| Electron 二进制在首次运行时才下载 | `electron/index.js` 发现 `path.txt` 不存在就调 `install.js` |
| electron-builder 26.18 认 `bun.lock` | 打包日志 `searching for node modules pm=bun` |

前两条决定了 Electron 的下载源只能靠环境变量 `ELECTRON_MIRROR`；后两条决定了 `just install` 要显式把二进制提前下好（之前 pnpm 配置里「放行 electron 的构建脚本」其实一直是空转的）。

## 验证

- `just install`、`just check`（27 个单测 + 构建）、`just smoke`（6 步）全部通过。
- `just package` 打出的 pacman 包：打进包里的生产依赖按包名与 pnpm 版**一个不缺、一个不多**（244 个），pi 的 8 个包都是 1.6.1。
- 244 个包里 214 个版本相同，30 个不同：26 个只是修订号（Bun 是全新解析，取到了范围内更新的版本），其余 4 个是 `@types/node`、`undici-types` 这类类型包和 `micromark-util-*` 的次版本。
- 对打出来的产物重跑自检，6 步通过。

## 后果

好的：

- 冷却期闸门没有了，pi 发新版当天就能跟。
- 安装更快，也没有 pnpm 那种配置文件迁移带来的静默失效。
- 与仓库规范「优先 Bun」一致。

代价与约束：

- **没有了冷却期这道供应链闸门**。装进来的可能是刚发布不久的版本，是否接受由项目所有者决定（本条即为记录）。
- Bun 只读 `bunfig.toml`，`.npmrc` 里除 registry / 鉴权外的键不认。下载源之类的配置只能走环境变量。
- 不能直接 `bun install` 了事：那样 Electron 二进制会留到首次运行才下载，而且会去连 GitHub。统一走 `just install`。
- `bun run` 不能加 `--bun`，否则构建工具会被放到 Bun 运行时上（未验证）。
- Bun 用的是扁平布局，不是 pnpm 那种依赖隔离的目录结构。传递依赖就摆在 `node_modules` 根上，import 了没声明的包（幽灵依赖）类型检查也照样能解析，**工具挡不住**。切换时核对过：源码里 import 的第三方包都在 `package.json` 里有声明。以后新增 import 时记得同步声明。
